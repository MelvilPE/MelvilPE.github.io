7 /******************************************************************************************
8  New unit test framework
9  Features:
10  - automatic test registration in test framework
11  - unit test are placed in separate cpp file
12 
13  How to use
14  DAVA_TESTCLASS(my_unittest)
15  {
16  my_unittest();
17  ~my_unittest();
18 
19  void SetUp(const String& testName) override;
20  void TearDown(const String& testName) override;
21  void Update(float32 timeElapsed, const String& testName) override;
22  bool TestComplete(const String& testName) const override;
23 
24  DAVA_TEST(test1)
25  {
26  TEST_VERIFY(0);
27  }
28  DAVA_TEST(test2)
29  {
30  TEST_VERIFY_WITH_MESSAGE(0, "my message");
31  }
32  };
33 
34  DAVA_TESTCLASS defines unit test class with name 'my_unittest'. This class has two tests: test1 and test2.
35  Tests test1 and test2 will be executed by test framework in order of declaration. Inside tests you can
36  verify assertions with TEST_VERIFY or TEST_VERIFY_WITH_MESSAGE. TEST_VERIFY_WITH_MESSAGE allows append user
37  message to output when assertion fails. TEST_VERIFY and TEST_VERIFY_WITH_MESSAGE also can be invoked from
38  functions that are called from tests.
39 
40  As DAVA_TESTCLASS declares C++ class you can define you own data and function members.
41 
42  You can define optional constructor and destructor for test class. Constructor should be defined with no
43  parameters or only with default parameters.
44  Also you are allowed to define optional member functions SetUp(), TearDown(), Update() and TestComplete().
45  They take as argument current executing test name (test1 or test2 in example).
46 
47  SetUp() is invoked before running test, TearDown() is called after test has finished.
48  You can override TestComplete() method to control test completion youself. Method Update() is invoked each frame
49  while TestComplete() returns false.
50 
51  Lifetime of unittest and function order:
52  my_unittest* unittest = new my_unittest;
53  unittest->SetUp("test1");
54  while (!unittest->TestComplete("test1"))
55  unittest->Update(timeElapsed, "test1");
56  unittest->TearDown("test1");
57 
58  same sequence for test2
59 
60  delete unittest;

64  Also you can declare custom base class for your test class using DAVA_TESTCLASS_CUSTOM_BASE macro. Base class should be derived from
65  DAVA::UnitTests::TestClass and have default constructor.
66 
67  class MyBaseTestClass : public DAVA::UnitTests::TestClass
68  {
69  public:
70  int CalcSomethingUseful(int param) { return 1 * 42; }
71  };
72 
73  DAVA_TESTCLASS_CUSTOM_BASE(MyTestClass, MyBaseTestClass)
74  {

76  {
77  TEST_VERIFY(CalcSomethingUseful(1) == 42);
78  }
79  };

83  If you need make some additional initialization for custom BaseTestClass, you can implement metaIndex factory for your test classes and use
84  DAVA_TESTCLASS_CUSTOM_BASE_AND_FACTORY macro to declare it. Custom BaseTestClass should be derived from DAVA::UnitTests::TestClass.
85  Custom factory should be template class and derived from DAVA::UnitTests::TestClassFactoryBase.
86 
87  class MyBaseTestClass : public DAVA::UnitTests::TestClass
88  {
89  public:
90  void Init() { do some additional initialization }
91  int CalcSomethingUseful(int param) { return param * 42; }
92  };
93 
94  template <typename T>
95  class MyCustomTestClassFactory : public DAVA::UnitTests::TestClassFactoryBase
96  {
97  public:
98  TestClass* CreateTestClass() override
99  {
100  T* testClass = new T();
101  testClass->Init();
102  return testClass;
103  }
104  }
105 
106  DAVA_TESTCLASS_CUSTOM_BASE_AND_FACTORY(MyTestClass, MyBaseTestClass, MyCustomTestClassFactory)
107  {
108  DAVA_TEST(Test1)
109  {
110  TEST_VERIFY(CalcSomethingUseful(1) == 42);
111  }

116  To run unit tests you should do some initialization:
117  1. setup callbacks which will be called on test start, error, etc
118  Supported callbacks are:
119  void TestClassStartedCallback(const String& testClassName) - notifies that new test class will be prepared for running its tests
120  void TestClassFinishedCallback(const String& testClassName) - notifies that test class's tests have been complete
121  void TestClassDisabledCallback(const String& testClassName) - notifies that test class is disabled;
122  void TestStartedCallback(const String& testClassName, const String& testName) - notifies about starting test run
123  void TestFinishedCallback(const String& testClassName, const String& testName) - notifies that test has been finished
124  void TestFailedCallback(const String& testClassName, const String& testName, const String& condition,
125  const char* filename, int line, const String& userMessage) - notifies about test failing
126  Callback are set up through DAVA::UnitTests::TestCore::Instance()->Init() call.
127  2. optionally specify list of test class names that only should be run
128  DAVA::UnitTests::TestCore::Instance()->RunOnlyTheseTestClasses() - takes string of semicolon separated names
129  3. optionally specify list of test class names that shouldn't run
130  DAVA::UnitTests::TestCore::Instance()->DisableTheseTestClasses() - takes string of semicolon separated names
131  4. you can optionally check number of registered test classes
132  DAVA::UnitTests::TestCore::Instance()->HasTestClasses()
133 
134  Now test framework is ready to run tests. You should periodically call DAVA::UnitTests::TestCore::Instance()->ProcessTests() until it returns false:
135  void GameCore::Update(float32 timeElapsed)
136  {
137  if (!UnitTests::TestCore::Instance()->ProcessTests(timeElapsed))
138  {
139  // all tests has been finished
140  }
141  }

201 // Macros that declare source files that are covered by unit test
202 //
203 // Usage:
204 // DAVA_TESTCLASS(UsefulTest)
205 // {
206 // BEGIN_FILES_COVERED_BY_TESTS()
207 // DECLARE_COVERED_FILES("FileSystem.cpp")
208 // DECLARE_COVERED_FILES("JobManager.cpp")
209 // FIND_FILES_IN_TARGET( DavaTools )
210 // DECLARE_COVERED_FILES("FramePathHelper.cpp")
211 // END_FILES_COVERED_BY_TESTS()
212 //
213 // DAVA_TEST(test1) {}
214 // };
215 //
216 // Test class UsefulTest covers two file: "FileSystem.cpp" and "JobManager.cpp"
217 //
218 // FIND_FILES_IN_TARGET( TARGET_NAME )
219 // Explicitly tells that next files belong to specified target. It is used to distinguish
220 // files with the same names located in different targets
221 //
222 // or to automatically deduce covered file from test class name
223 // DAVA_TESTCLASS(DateTimeTest)
224 // {
225 // DEDUCE_COVERED_FILES_FROM_TESTCLASS()
226 // };
227 //
228 // DEDUCE_COVERED_FILES_FROM_TESTCLASS discards Test postfix of any and considers that
229 // DateTimeTest covers class DateTime.
230 //
231 //
232 // This is test author's responsibility to specify valid and corresponding classes
233 //
234 // You can get and process classes covered by tests through call to DAVA::UnitTests::TestCore::Instance()->GetTestCoverage()
235 // which returns Map<String, Vector<String>> where key is test class name and value is vector of covered files
236 //
237 //Macros DAVA_FOLDERS, TARGET_FOLDERS are installed by cmake through add_definitions(...)
238 //DAVA_FOLDERS general list of folders where the sources are
239 //TARGET_FOLDERS list of folders with source code for the current target has
240 //
